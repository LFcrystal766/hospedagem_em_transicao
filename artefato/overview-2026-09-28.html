Hospedagem nova

O que a Hostinger muda no plano

O plano pedia "LiteSpeed + cPanel com token de API". A Hostinger tem LiteSpeed, SSH com WP-CLI, datacenter em São Paulo e uma API própria com 51 endpoints de hospedagem, mas o painel é o hPanel, não o cPanel. Cinco itens da fase da cópia mudam de mecanismo, nenhum muda de objetivo.

Atende

LiteSpeed, PHP 7.4, São Paulo

Cache de página igual ao de hoje. A versão do PHP e as extensões mudam pela API (php/version, php/extensions). O datacenter é escolhido ao criar o site: conferir com GET /api/hosting/v1/datacenters e pedir São Paulo.

Atende, pelo painel

SSH e WP-CLI

Disponível nos planos Premium ou acima, desligado por padrão. Ativar em Websites > Dashboard > SSH Access e colar a chave pública. Porta 65002. A partir daí, purge, regeneração de CSS do Elementor, checksums e conferência do banco são WP-CLI, como o plano previa.

Atende, pela API

Restaurar a cópia

POST .../wordpress/import importa um WordPress a partir de arquivo + dump de banco já enviados pro diretório do site (por SSH). Alternativa: o pedido de migração do hPanel aceita o backup completo do cPanel. O import sobrescreve o site de destino: só rodar num site vazio.

Muda de mecanismo

Origin CA

A API só instala o certificado gratuito da própria Hostinger. O Origin CA do Cloudflare entra pelo hPanel: SSL > Import SSL, com certificado e chave privada. Sem esse passo o degrau 3 fica sem Full (strict), então ele vem antes da virada, como no plano.

Decidir

IPv6

Hospedagem compartilhada da Hostinger costuma entregar só IPv4. Se o hPanel não mostrar IPv6, o AAAA do apex é apagado no degrau 3, no mesmo minuto do A. AAAA velho = parte das visitas caindo na AZAN sem ninguém perceber.

Não fazer

Integração Cloudflare do hPanel e troca de NS

O hPanel oferece "ativar Cloudflare" e o e-mail de boas-vindas pede pra apontar os NS. Nenhum dos dois: a zona é a nossa, o server. do Stape e o mail. só existem nela. Só o IPv4 (e IPv6, se houver) da Hostinger entra no Cloudflare, e só no degrau 3.

Conferir na cópia

IP real do visitante

Atrás do laranja, o sGTM e o WordPress veem o IP do Cloudflare se a origem não ler CF-Connecting-IP. Testar com uma página de eco na cópia via curl --resolve antes do degrau 3. O firewall da Hostinger já convive com as faixas do Cloudflare.

Opção nova

E-mail @crystalnowpp

Os planos de hospedagem incluem caixas de e-mail. Vira a terceira opção do item decidir-email, ao lado do Email Routing do Cloudflare e do Google Workspace. A decisão continua dependendo da lista de caixas em uso, que sai do token cPanel da AZAN.

Atende, pela API

Cache e observabilidade

litespeed-cache/status e /purge, memcached/toggle, cache/clear, listagem de arquivos e conteúdo (só leitura), redirects e cron jobs. O que o plano fazia por UAPI do cPanel, aqui é REST com bearer token.
